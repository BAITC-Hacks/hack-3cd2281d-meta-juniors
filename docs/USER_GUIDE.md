# Самостоятельная проверка Career Quest

Руководство для участника команды и проверяющего репозиторий. Время основного прохода — ориентировочно 10–15 минут. [Запуск](../README.md#быстрый-запуск) · [фактический QA](QA_REPORT.md) · [известные баги](BUG_REPORT.md).

## 1. Запустить проект

В терминале из корня репозитория:

```sh
docker compose up --build -d
docker compose ps
```

Дождаться готовности web и db, открыть http://127.0.0.1:8000. При первом запуске нужны загрузка образов, миграции и импорт данных; сразу после команды страница может быть ещё недоступна. Логи: `docker compose logs --tail=50 web`.

На свежей базе есть 200 сотрудников и 2743 истории; дата среза — 01.10.2026. Перезапуск сохраняет базу.

## 2. Проверить сотрудника

Войти кнопкой «Я сотрудник» либо логином `employee`, пароль по умолчанию `career-demo-2026`.

| Действие | Ожидание на свежей базе |
|---|---|
| Открыть профиль E0028 | Backend Engineer, Middle; цель Senior; покрытие 72% |
| Посмотреть навыки | System Design 3/4; API Design 4/4; Cloud Platforms 1/3 |
| Посмотреть историю | 17 записей; учитываются завершения после аттестации |
| Посмотреть рекомендации без ключа | Пометка «Подбор по правилам»; до трёх допустимых шагов с фактами |
| Открыть «Подробнее» у Cloud Certification Prep / EV_009 | 40 часов, формат в своём темпе, Cloud 1→2; CI/CD 3→3 |

Покрытие означает долю требований по навыкам. **100% не является решением о повышении.** Если для разрыва нет подходящего события, приложение сообщает об ограничении каталога.

## 3. Пройти личный план

1. В EV_009 нажать «Добавить в мой план +».
2. Убедиться, что шаг находится в «Запланировано». Навыки пока не меняются.
3. Нажать «Начать в демо»: шаг перемещается в «В процессе», навыки всё ещё не начислены.
4. Нажать «Завершить в демо ✓»: шаг находится в «Завершено».
5. Вернуться в профиль: покрытие **74%**, Cloud **2**, CI/CD **3**, история **18 записей**.
6. Перезагрузить страницу: результат сохраняется.

100% выполнения одного шага в плане отличается от 74% покрытия карьерной цели. «Начать/завершить в демо» моделируют обучение на дату среза, в том числе для будущих сессий.

Неначатый шаг можно убрать. После смены карьерной цели план сохраняется; пригодность неначатых шагов перепроверяется. При DEMO_MODE=0 симуляция начала/завершения отключена.

## 4. Проверить HR

Выйти, войти «Я HR» (`hr`, тот же демо-пароль).

- Найти E0028: после указанного завершения HR показывает **74%** и **4 завершения за 90 дней**.
- Очистить поиск; выбрать грейд Middle, разрыв Cloud Platforms и «Нужна поддержка». Нажать «Применить фильтры».
- Проверить, что таблица и сводка относятся к одной выборке. Дефициты навыков открывают соответствующих сотрудников.
- Открыть профиль и план сотрудника: HR просматривает их, но не меняет чужую цель/план/завершение.

Сигнал поддержки основан на участии за 90 дней. В текущей версии отсутствуют отдельный срез без рекомендованного шага и участие по мероприятиям — см. BUG-01/02.

## 5. Загрузить проверочные профили

Готовые синтетические файлы:

- [employees.json](qa/2026-09-23/fixtures/employees.json)
- [activity_history.csv](qa/2026-09-23/fixtures/activity_history.csv)

HR → «Загрузка данных» → выбрать оба файла → «Проверить файлы и посмотреть изменения ↗».

До подтверждения данные не должны измениться. Предпросмотр свежей базы показывает **3 новых сотрудника и 6 новых историй**. Нажать «Подтвердить загрузку», затем открыть новые профили:

| Профиль | Что проверить |
|---|---|
| QA001 | 92%; подбор учитывает критичный System Design, цель и историю, а не только минимальный навык |
| QA002 | 100%; нет подходящих активностей, дано объяснение выполнения требований |
| QA003 | 97%; предлагается EV_006, прогноз System Design 4→5, Observability 3→4, API Design остаётся 5 |

Новые профили доступны HR; аккаунты сотрудников для них автоматически не создаются. Предпросмотр действует 30 минут; при изменении данных нужно загрузить файлы заново. Повторное подтверждение уже выполненного импорта не дублирует записи.

Для проверки отказа загрузить [invalid_employees.json](qa/2026-09-23/fixtures/invalid_employees.json): уровень навыка 6 должен быть отклонён. Не использовать рабочие данные команды для негативных тестов.

## 6. Сверить результат и остановить

Открыть [QA_REPORT.md](QA_REPORT.md): там указаны проверенный commit, методы, результаты и ограничения. Если код уже изменён, прежние статусы требуют перепроверки.

```sh
docker compose down
```

Эта команда сохраняет volume. Для воспроизводимых начальных 72% нужен отдельный свежий QA-стенд; повторное открытие сайта не сбрасывает прогресс.

## Если что-то не запускается

| Симптом | Действие |
|---|---|
| Docker недоступен | Запустить Docker Desktop и дождаться готовности движка |
| Страница сразу после старта не отвечает | Проверить `docker compose ps` и логи web; дождаться начального импорта |
| Порт занят | В локальном .env задать APP_PORT=8001; при конфликте БД — POSTGRES_PORT=5434; повторить запуск |
| AI-ключа нет | Проверять явно обозначенный подбор по правилам; live-AI остаётся непроверенным |
| Контрольные числа отличаются | Проверить цель, историю и прошлые завершения: база сохраняется между запусками |
| Найдена ошибка | Записать commit, роль, адрес, шаги, ожидание, факт и приложить скриншот; шаблон есть в QA_PLAN.md |

Не загружать .env, API-ключи, cookies и реальные персональные данные в репозиторий.
