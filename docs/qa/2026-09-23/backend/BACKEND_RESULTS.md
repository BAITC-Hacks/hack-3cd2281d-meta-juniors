## Подтверждённые дефекты

### BE-01 — повтор завершения через импорт завышает уровень навыка (P1)

Связанные пункты плана: CQ-05, CQ-06, CQ-07, REC-01, REC-02.

1. Взять синтетическую копию профиля E0028, заменить `employee_id` на `JUDGE_AUDIT`.
2. Как HR загрузить этот профиль вместе с историей: две записи `completed` для `EV_009`, даты `2026-09-20` и `2026-09-21`, разные `record_id`, `completion_pct=100`.
3. Прочитать рассчитанные навыки импортированного сотрудника.

Ожидание: отклонить недопустимый повтор атомарно или применить рост неповторяемой активности только один раз. `data/README.ru.md:122` разрешает повтор после `completed` только для `EV_036`.

Факт: обе записи приняты, Cloud растёт **1 → 3**, хотя однократное прохождение `EV_009` даёт **1 → 2**. Это влияет на прогресс и последующий подбор шагов.

Тест: `test_nonrepeatable_event_cannot_gain_twice_from_imported_history`, `qa_backend_extra.py:208`.

Доказательство в журнале: `AUDIT_DOUBLE_COMPLETION baseline_cloud 1 after_cloud 3 records 2`.

Места в приложении: `quest/services/importer.py:117` проверяет ссылки и конфликт по `record_id`, но не повтор `completed` для пары сотрудник / неповторяемое событие; `quest/services/career.py:41` и `:47` применяют рост для каждой такой записи.

### BE-02 — неверный тип JSON вызывает HTTP 500 в complete API (P2)

Связанный пункт плана: REC-02; дополнительная проверка входа API.

1. Войти как владелец E0028 и получить действительный CSRF-токен.
2. Отправить `POST /api/people/E0028/complete/EV_009/`, `Content-Type: application/json`, тело `[]`.
3. Повторить с телами `"bad"`, `42`, `true`, `null`.

Ожидание: HTTP 400 с ошибкой формата, без изменения данных.

Факт: все пять вариантов возвращают **HTTP 500** из-за `AttributeError` при `request.data.get(...)`. Отсутствующий или неверный UUID внутри нормального JSON-объекта корректно даёт 400. Мутации данных в этих ошибочных запросах не обнаружены.

Тест: `test_completion_non_object_json_is_client_error_not_server_error`, `qa_backend_extra.py:139`.

Доказательство в журнале: `AUDIT_NON_OBJECT [] 500 AttributeError("'list' object has no attribute 'get'")`, аналогичные строки для остальных типов.

Место: `quest/views.py:169`; обработчик перехватывает `ValueError`, но до проверки UUID не валидирует объектную структуру входа.

### BE-03 — CSV с неверным заголовком объявляется успешно загруженным (P2)

Связанный пункт плана: REC-02.

1. Войти как HR, отправить на `/hr/import/` поле `history` с файлом `activity_history.csv`.
2. Содержимое файла — единственная строка `not_a_dataset` и перевод строки.

Ожидание: понятная ошибка схемы CSV, состояние набора данных не меняется.

Факт: **HTTP 200**, сообщение «Данные загружены. Новые профили доступны на HR-экране», обработано 0 записей; `DatasetState.revision` изменился **1 → 2**. Заголовки CSV не проверяются, когда нет строк для валидации. HTTP 200 сам по себе не ошибка — проблема в ложном сообщении об успехе и отсутствии проверки схемы.

Тест: `test_history_with_wrong_header_is_rejected`, `qa_backend_extra.py:263`.

Доказательство: `AUDIT_WRONG_CSV_HEADER http 200 revision_before 1 revision_after 2`; HTML с `notice success` сохранён в журнале.

Места: `quest/services/importer.py:23` и `:44` — пустой результат `DictReader` минует проверку записей; `:146` увеличивает ревизию; `quest/views.py:112` сообщает об успехе.

## Что дополнительно подтвердилось

- С действительным CSRF сотрудник не может изменять цель/завершать активность/запрашивать рекомендации чужого профиля (404) и импортировать (403). HR не может выбирать цель или отмечать выполнение за сотрудника (403). Контрольный POST владельца с CSRF успешен, без CSRF отклонён.
- Неверные цели отклоняются без изменения состояния; завершение выключено вне деморежима. Неизвестная активность возвращает 404, неподходящая аудитория/требования/потолок роста — 409.
- Обычное завершение E0028 → EV_009 даёт Cloud 1 → 2, покрытие 72% → 74%, сбрасывает кэш. Повтор того же `request_id` не начисляет рост, новый запрос повторного завершения даёт 409. Повтор того же ключа для другой активности даёт 409.
- HR-показатели после завершения пересчитывают покрытие и число завершений за 90 дней. Это не доказывает полноту всех требуемых разделов HR-экрана.
- HR импортирует дополнительный профиль **со связанной историей** через HTTP; история участвует в расчёте уровня и подборе. Неизвестные ссылки на событие/сотрудника/навык/руководителя/цель, неверные JSON/UTF-8 и несогласованный статус истории отклоняются атомарно.
- Контрпример с минимальным Public Speaking, тремя пропусками и критичным System Design пройден в режиме правил.
- Некорректные результаты AI, выдуманное событие/доказательство, дублированный выбор и ошибка провайдера приводят к явно обозначенному режиму правил. Мок тайм-аута подтверждает обращение к `future.result(timeout=8)`, отмену future и fallback.
- При смоделированном отказе сохранения сервер не сообщает об успехе и не сохраняет частичные данные; возвращается 500. Удобство сообщения в браузере этой backend-проверкой не подтверждено.

## Ограничения и воспроизведение

Живые вызовы OpenAI **не выполнялись**, ключ перед запуском обнулён. Дополнительные проверки ставят заглушку на конструктор OpenAI; сценарии AI подменяют метод выбора / future. 51 мс в тесте тайм-аута — время ответа с моками, не измерение реального AI и не подтверждение SLA 10 секунд.

HTTP-сценарии выполнены Django test client с реальным контролем CSRF на изолированной БД; это не браузерная проверка отрисовки и не замер сети. Нагрузочное тестирование и гонки конкурентных запросов не выполнялись. Проверка чистого запуска одной командой и UI выполняется отдельно.

Для повторения после исправления скопировать `qa_backend_extra.py` в `/tmp/` контейнера и выполнить из каталога той же Compose-сборки:

```powershell
docker compose exec -T -e OPENAI_API_KEY= -e PYTHONPATH=/tmp:/app web python manage.py test qa_backend_extra --verbosity 2 --noinput
```

Этот модуль намеренно проверяет ожидаемое поведение и остаётся красным на трёх дефектах версии `0534bf7`. Исправления приложения в рамках аудита не вносились.
