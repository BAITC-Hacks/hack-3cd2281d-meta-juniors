## Что загружать

- Положительный сценарий CQ-05: **employees.json** и **activity_history.csv** вместе через HR → «Загрузка данных». В пакете ровно три новых профиля: QA001, QA002, QA003, и шесть связанных строк истории. Каталоги уже должны быть загружены из исходного кита.
- Для будущей проверки CLI использует стандартные имена `employees.json` и `activity_history.csv` в этой папке. Негативные файлы названы иначе и штатной командой импорта каталога не подхватываются.
- На свежем ките ожидается **203 сотрудника и 2 749 записей истории** вместо 200 и 2 743. Исходные ID E0001–E0200 не входят в новый JSON. При повторной загрузке те же ID должны обновляться без дубликатов; после демо-завершений повторный импорт не является сбросом базы.
- Новые профили доступны HR. Импорт не создаёт им отдельные учётные записи сотрудников. Адреса для HR: `/people/QA001/`, `/people/QA002/`, `/people/QA003/`.

Все события ниже добровольные, соответствуют роли/грейду, имеют будущие сессии и ещё не завершены профилем. У EV_006/007 предпосылка System Design ≥ 2 выполнена.

| EV_006 | Designing High-Load Systems | 2026-10-07 | System Design 2 → 3; API Design 4 → 4; Observability 3 → 4 |

Для QA003 EV_006 доступен 2026-10-07; текущий Senior и System Design = 4 удовлетворяют условиям участия. Завершение в демо моделируется на дату среза, как описано в README приложения.

### Контроль прогресса

Проценты ниже рассчитаны независимо по формуле текущего приложения: сумма `min(текущий уровень, требуемый уровень)` / сумма требований, с округлением до целого. Это покрытие требований, а не обещание повышения.

| Профиль | До | После однократного завершения EV_006 |
|---|---|---|
| QA001 | 46 / 50 = **92%** | 47 / 50 = **94%** |
| QA002 | 50 / 50 = **100%** | Завершение не требуется: полезного шага нет |
| QA003 | 60 / 62 ≈ **97%** | 62 / 62 = **100%** |

Для QA003 повтор того же запроса завершения не должен добавлять ещё одну запись участия или повышать навыки повторно. Первая фиксация добавляет одну запись истории; исходные шесть строк фикстуры сохраняются. Контрольные числа действуют до других действий, меняющих навыки/цель.

## Негативный импорт — REC-02

Выполнять по одному после положительного импорта, фиксируя состояние до/после.

1. **invalid_employees.json**: синтаксис JSON корректен, но у существующего QA001 `skills.SK_SYSTEM_DESIGN = 6`, что нарушает шкалу 0–5. Ожидается понятная ошибка с полем `skills.SK_SYSTEM_DESIGN`; валидный QA001 должен сохранить уровень 2. Файл не содержит четвёртого нового ID.
2. **invalid_history_unknown_event.csv**: формат строки корректен, QA001 существует, но `event_id = EV_UNKNOWN_QA` отсутствует в каталоге. Ожидается отказ из-за неизвестного мероприятия (`record_id = QA_NEG_UNKNOWN_EVENT`), эта запись не сохраняется.

По коду импорта весь пакет обрабатывается атомарно: негативные попытки не должны менять профили, историю и число записей. Это ожидание для ручной проверки, а не уже полученный результат.

## Выполненная статическая проверка

Проверены реальные Pydantic-описания EmployeeInput/HistoryInput без инициализации Django; типы и диапазоны навыков, имена полей CSV, роли/цели, менеджер, существование навыков и мероприятий, отсутствие совпадений с исходными ID, даты, стаж, правила статусов и условия участия. Ошибочный JSON предсказуемо не проходит проверку диапазона; ошибочный CSV проходит схему строки, но не проверку ссылки на каталог. Независимая арифметика и список полезных событий получены из сырых данных, без вызова сервисов приложения.
