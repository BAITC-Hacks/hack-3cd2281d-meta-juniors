# Сценарий защиты: 3 минуты

Для самостоятельной проверки проекта используйте [руководство пользователя и проверяющего](USER_GUIDE.md). Фактические результаты и ограничения собраны в [QA_REPORT.md](QA_REPORT.md), а открытые дефекты — в [BUG_REPORT.md](BUG_REPORT.md).

1. **Проблема — 20 с.** Каталог обучения сам по себе не объясняет сотруднику, что поможет достичь карьерной цели. Career Quest учитывает текущие навыки, историю участия и требования целевой роли и предлагает 1–3 понятных шага.
2. **Рекомендация — 45 с.** Войти как HR, найти E0001 и открыть профиль. Показать цель Middle Backend, критичный разрыв и карточку System Design Fundamentals: API Design 2 → 3, System Design 1 → 2. Раскрыть «Почему этот шаг подходит». AI выбирает только из допустимых событий и опирается на проверяемые факты. Плашка честно показывает AI или резерв по правилам.
3. **Учёт истории — 30 с.** Открыть E0028: после Designing High-Load Systems навык System Design уже 3, поэтому курс с потолком 3 повторно не рекомендуем. Для Senior нужен 4, каталог это пока не закрывает. Предлагаем обсудить практику с координатором и экспертом.
4. **Действие и результат — 35 с.** Войти как employee, открыть «Мой план», показать страницу результата. На чистом наборе можно добавить рекомендацию и начать. Прогноз отделён от факта; навыки растут после проверенного результата. На машине команды три шага уже завершены в раннем демо — это отмеченная история без проверки, не новая демонстрация экспертной оценки.
5. **Ценность для HR — 25 с.** Вернуться в HR. Показать дефициты команды, фильтр по навыку и согласованный список сотрудников. Сигнал поддержки нужен для разговора, это не диагноз и не рейтинг людей.
6. **Проверяемость — 25 с.** Открыть «Загрузка данных»: неизвестные профили и история проходят предпросмотр и подтверждение, после чего сразу получают рекомендации. Запуск — одна Docker Compose-команда. Результат: сотруднику понятен следующий шаг, HR видит потребность команды.

## До выхода к жюри

- Проверить основной сайт на http://localhost:8001 и вход обеих ролей. В новом клоне порт по умолчанию 8000.
- Для рекомендаций на текущей базе использовать E0001 через HR. У E0028 уже завершены три подходящих исходных шага, пустой новый подбор ожидаем.
- Подготовить вкладки: профиль E0001, профиль E0028, HR-обзор, загрузка данных. HR может смотреть профиль, но не менять план за сотрудника.
- Прогнать текст защиты за 3 минуты. Порядок карточек зависит от модели; проверять объяснения и числа, не обещать фиксированный порядок.

## Дополнительный сценарий: индивидуальная практика

Показывать, если осталось время или жюри спрашивает, что делать при неполном каталоге.

1. Сотрудник E0028 запрашивает практику System Design 3 → 4.
2. HR согласует со специалистом задание и критерии. В прототипе подготовлен редактируемый кейс сервиса уведомлений.
3. Сотрудник добровольно добавляет задание в план, начинает и отправляет решение/ссылку. Прогноз меняется, фактический навык ещё нет.
4. Проверяющий через HR-кабинет возвращает с комментарием или подтверждает все критерии. Версии работы сохраняются. После подтверждения навык 3 → 4; повторное подтверждение не начисляет прирост снова.

## Репетиция без потери данных

В рабочей базе E0028 уже есть три завершения из предыдущего демо — они сохранены. Для System Design всё ещё можно запросить новую практику. После одобрения она не начисляется повторно: для повторной демонстрации полного цикла используйте отдельный стенд или дополнительный синтетический профиль, не сбрасывая рабочую базу.

На чистом наборе одно подтверждение System Design даёт покрытие 72% → 74%. В текущей базе итог зависит от уже завершённых шагов: ориентируйтесь на показанные приложением числа.

HR — координатор, не универсальный технический экзаменатор. Отдельного назначения экспертов пока нет: проверка выполняется через общий HR-кабинет. Черновик задания подготовлен командой и утверждается после согласования с компетентным специалистом. Это не курс исходного каталога и не результат генерации AI. У исходных мероприятий доступны описание и форма отчёта, но материалы обучения не предоставлены.

## Работа команды

- Разработчик: код, интеграция, содержательные коммиты в официальный репозиторий.
- Аналитик/QA: объясняет AS-IS → TO-BE, историю E0028 и смысл подтверждённого результата.
- Документация/QA: чистый запуск по README, проверки на другом устройстве, скриншоты и репетиция демонстрации. Правки README/docs в своей ветке.

Перед защитой проверьте фактическую плашку AI-режима и сеть. Резерв по правилам нельзя называть ответом LLM. Проверка в прототипе доступна через HR-кабинет; интеграции с LMS и автоматической аттестации нет. Прирост — модель по правилам синтетического датасета, не объективная аттестация или гарантия повышения. Эффект на вовлечённость пока не измерен.
