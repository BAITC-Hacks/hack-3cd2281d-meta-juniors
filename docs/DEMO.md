3. **Подбор — 45 с.** Показать до трёх шагов и факты: разрыв, история, нагрузка. Обратить внимание: EV_005 не рекомендуется, потому что его потолок уже достигнут; доступное мероприятие, которое даст System Design 4, отсутствует. Приложение честно показывает этот разрыв.

5. **HR — 25 с.** Выйти, войти как hr. Выбрать Middle, Cloud Platforms, «Нужна поддержка»: список людей и показатели пересчитываются вместе. Дефициты кликабельны; рейтинга сотрудников нет.
6. **Профили жюри — 25 с.** «Загрузка данных»: employees.json + activity_history.csv → предпросмотр количества новых и изменяемых записей → подтверждение → ссылка на новый профиль. При ошибке весь импорт отменяется; изменения кода не нужны.

Если в текущей демобазе E0028 уже завершил все подходящие мероприятия, пустой подбор корректен: выполненные одноразовые события не рекомендуются снова. Для повторной демонстрации нужен отдельный чистый стенд со стартовыми данными; рабочую базу команды не сбрасывать.

Перед защитой проверьте: AI-ключ подключён, плашка действительно «AI-рекомендация», объяснения корректны; есть сеть. Если работает резерв, называйте его резервом, а не LLM. Проверьте чистый запуск на другом устройстве. Не заявляйте эффект на вовлечённость как измеренный результат.

## Параллельная работа команды

- Разработчик: код и интеграция; содержательные коммиты в официальный репозиторий.
- Аналитик/QA: тестирует нетипичные профили, сверяет объяснения с данными, фиксирует шаги воспроизведения ошибок.
- Документация/QA: чистый запуск по README, мобильный интерфейс, скриншоты, сценарий демонстрации. Правки README/docs в своей ветке.

Новые обязательные тесты и найденные проблемы записывать в Discovery Matrix. Не отмечать live-AI, latency AI или запуск на чужом устройстве как проверенные без фактического результата.
