# Career Quest: решения и ограничения

## Поток данных

JSON/CSV → Pydantic validation → atomic import → PostgreSQL → current skills → target gaps → eligible events → LLM selection → server validation → UI.

В одном Django-приложении находятся серверные страницы и DRF API. Расчёты отделены от views: `quest/services/career.py`. AI-адаптер: `recommendations.py`. Импорт: `importer.py`. Интерфейс использует Django Templates, локальный Bootstrap grid и собственные CSS/JS. Внешних CDN-запросов при работе страницы нет.

## Актуальные навыки

`employees.skills` — результат последней аттестации. Хронологически применяются completed после `last_review_date`, до даты среза включительно. Для каждого эффекта:

`new = max(old, min(5, max_level, old + gain))`

База аттестации не перезаписывается при завершении, поэтому повторное вычисление не начисляет баллы дважды. Новый демо-результат в день аттестации учитывается как результат после неё. В исходных self_paced-записях нет completed_at: поле date используется как приближение даты завершения; это ограничение исходного набора.

## Цель и допустимость

Явная career_goal приоритетна. При отсутствии предлагается следующий грейд той же роли; для Lead требуется выбор цели. Прогресс — доля покрытых уровней из целевого профиля, без обещания повышения.

Исключаются mandatory, неподходящие текущие role/grade, невыполненные prerequisites, отсутствие будущих сессий (кроме self_paced), in_progress и уже completed. EV_036 допускает повтор в другую дату. Смена карьерной цели не отменяет ограничения аудитории мероприятия. Кандидат обязан реально сокращать хотя бы один разрыв к цели.

## AI и объяснимость

OpenAI Responses API, Structured Outputs, Pydantic. Настраиваемая модель, по умолчанию gpt-4.1-mini. LLM выбирает порядок и до трёх допустимых событий, а также факты, объясняющие выбор. Для каждого события объяснение обязательно включает разрыв навыка и историю. Сервер отвергает неизвестные/повторные event_id, выдуманные evidence_id, неподтверждённую критичность. Тексты фактов строятся сервером: модель не может подменить числа или придумать причину отказа.

В запрос входят роль, грейд, стаж, формат работы, цель, разрывы и агрегированные признаки кандидатов. Имена сотрудников, их ID и сырые строки истории не отправляются. `store=False`; это настройка хранения Responses, а не гарантия отсутствия любого хранения у провайдера. Все строки датасета считаются недоверенными данными.

Один запрос без автоматических повторов; сетевой timeout 7 с, ожидание результата максимум 8 с. Ограниченный пул из 4 потоков. При ошибке, отказе, истечении ожидания или провале валидации используется явно обозначенный подбор по правилам. Ожидание не блокирует загрузку страницы: браузер запрашивает рекомендации отдельно. Результаты кэшируются на 10 минут (резервные — на 1 минуту) с отпечатком данных, модели и версии правил.

Резервный балл: 10 × закрываемые уровни (критичный вес 4, остальные 1), поправки на долю завершений похожих мероприятий за 180 дней, пропуски/отказы/прерывания, совместимость с удалённой работой и нагрузку. Веса — эвристика команды, не критерии жюри и не обученная модель. Пропуски не являются абсолютным запретом. При пустом списке показываются причина и оставшиеся разрывы.

## Права и завершение

Сессии Django, CSRF для изменений. Employee видит только связанный профиль. HR видит синтетические профили и агрегаты, может импортировать наборы; не меняет цель и не завершает обучение за сотрудника. HR — отдельная группа, без доступа к Django admin по умолчанию.

В демо владелец профиля может смоделировать завершение на дату среза, включая запланированные мероприятия. Это подписано в интерфейсе; фактическое обучение не подтверждается. Для промышленного использования нужен источник подтверждений из LMS. При DEMO_MODE=0 симуляция отключена.

Транзакция блокирует строку Employee. request_id уникален и привязан к сотруднику/событию; повтор того же запроса возвращает старый результат, другой запрос не позволяет повторить уже завершённую активность.

## HR

Дефициты считаются относительно индивидуальных целей. Сигнал поддержки: за 90 дней нет добровольных завершений или есть ≥2 пропуска/отказа/прерывания. Это наблюдаемая эвристика для разговора, не прогноз увольнения и не диагноз. Список по ID; публичного рейтинга нет.

## Известные ограничения

- Русский интерфейс; названия навыков/мероприятий сохранены из английского каталога. Полной kk/ru-локализации нет.
- Нет интеграции с корпоративной LMS/SSO и доказательств реального влияния на вовлечённость.
- Повторные обязательные мероприятия сохраняются как в исходном CSV, хотя общее правило README запрещает повторы. Они не рекомендуются и не дают игровые награды.
- Локальная проверка 200 профилей не заменяет нагрузочное тестирование крупной организации.
- Работа реального AI зависит от действующего API-ключа, доступа к выбранной модели и сети. Резервный режим не подтверждает качество live-AI.
