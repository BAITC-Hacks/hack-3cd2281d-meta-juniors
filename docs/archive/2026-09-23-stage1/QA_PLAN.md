## С чего начать проверяющему

1. Получить от разработчика точную версию/commit, адрес приложения или инструкцию запуска, способ входа сотрудником и HR, список известных ошибок и подтверждение режима AI.
2. Записать устройство, браузер, версию данных и состояние базы. Для числовых примеров ниже нужна свежая база из исходного кита, без ранее завершённых демо-активностей и изменённой цели.
3. В актуальной копии приложения пройти README: `docker compose up --build -d`, затем открыть `http://localhost:8000`. Нужен работающий Docker. При изменённом `APP_PORT` использовать соответствующий адрес. Эта команда неприменима к старой локальной папке, содержащей только черновики документации.
4. Вход из README текущей версии: `employee` и `hr`, демонстрационный пароль по умолчанию `career-demo-2026`. Если разработчик изменил его, использовать новые демо-доступы.
5. Сначала пройти запуск → профиль → рекомендацию → завершение → HR. Затем импорт новых данных, права, ошибки и измерения.
6. Для каждого сценария записывать результат и доказательство. После исправления повторять ошибочный сценарий и связанный основной путь на новом commit.

В отчёте остаются непроверенными реальный вызов OpenAI, качество и время ответа live-AI, а также чистый запуск на другом устройстве. HTTP-замеры из отчёта не включают отрисовку браузера. Режим «Подбор по правилам» нужно фиксировать отдельно: его успешная работа не подтверждает вызов LLM.

### Проверки прав с фактическими адресами

Войдя как `employee` (E0028), открыть в этом же браузере:

- `/people/E0028/` и `/api/people/E0028/` — свой профиль доступен.
- `/hr/` и `/hr/import/` — отказ в доступе, в текущем коде HTTP 403.
- `/people/E0001/` и `/api/people/E0001/` — чужой профиль не раскрывается, в текущем коде HTTP 404.

После входа как HR профиль, HR-экран и импорт доступны. POST-запросы изменения цели/завершения требуют отдельной проверки с действующим CSRF-токеном: отказ из-за отсутствующего токена не доказывает корректность прав. В этой версии отдельного `/api/hr/` нет.

В [hr_summary](https://github.com/BAITC-Hacks/hack-3cd2281d-meta-juniors/blob/0534bf797be825d2cfb04ec56604792a5d72f78d/quest/services/career.py#L228) и [HR-шаблоне](https://github.com/BAITC-Hacks/hack-3cd2281d-meta-juniors/blob/0534bf797be825d2cfb04ec56604792a5d72f78d/templates/quest/hr.html) найдены два пропуска относительно ТЗ:

- Нет участия, сгруппированного по активностям. Сейчас показаны завершения/пропуски по сотрудникам за 90 дней.

Передать разработчику и включить в CQ-08. Это статические замечания к `0534bf7`; после исправления подтвердить результат в приложении.
