# QA-отчёт Career Quest

## Карточка проверки

- Версия или commit: заполнить перед проверкой
- Дата и время: заполнить
- Тестировщик: заполнить
- Окружение и браузер: заполнить
- Роль для входа: сотрудник / HR
- Набор данных: указать версию стартового набора
- Статус отчёта: проверка не начата

## Как вести чек-лист

Для каждой проверки укажите фактический результат и приложите доказательство: скриншот, ссылку на Issue, лог или измерение. Отмечайте «Пройдено» только после реального выполнения сценария. Если проверка заблокирована, укажите причину и что нужно для продолжения.

Допустимые статусы: Не начато, Пройдено, Провалено, Заблокировано.

Создайте отдельный GitHub Issue для каждой ошибки. Укажите:

- Заголовок:
- Проверка (ID):
- Дата:
- Версия или commit:
- Устройство, ОС и браузер:
- Роль и тестовый профиль:
- Шаги воспроизведения:
- Ожидаемый результат:
- Фактический результат:
- Критичность: блокирующая / высокая / средняя / низкая
- Скриншот, лог или ссылка:
- Статус повторной проверки:

Не прикладывайте реальные персональные данные. Используйте синтетические профили из стартового набора.
