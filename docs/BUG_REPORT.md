## BUG-04 · P2 · Неверный тип JSON вызывает HTTP 500

**Связанный сценарий:** REC-02, вход completion API.

**Шаги:**

1. Войти сотрудником E0028, получить действительный CSRF-токен.
2. Отправить POST /api/people/E0028/complete/EV_009/ с Content-Type: application/json и телом [].
3. Повторить с JSON-строкой, числом 42, true и null.

**Ожидание:** HTTP 400 и объяснение, что требуется объект с корректным request_id. Данные не изменяются.

**Факт:** все пять вариантов дают HTTP 500 из-за AttributeError при request.data.get(...). Проверено Django test client с контролем CSRF; запись прогресса в этих запросах не произошла.

**Где исправлять:** [quest/views.py:169](https://github.com/BAITC-Hacks/hack-3cd2281d-meta-juniors/blob/0534bf797be825d2cfb04ec56604792a5d72f78d/quest/views.py#L169).

**Рекомендация:** до вызова get валидировать тип тела через serializer/схему; затем валидировать UUID. Не маскировать неожиданные ошибки общим подавлением исключений.

**Тест:** test_completion_non_object_json_is_client_error_not_server_error. [Журнал](qa/2026-09-23/backend/extra-suite.log).

## Отдельный риск RISK-01 — завершение через HTTP LAN-IP

**Статический вывод; в браузере на LAN не воспроизводился. В число шести дефектов не включён.**

В static/app.js:60–64 кнопка отключается, затем вызывается crypto.randomUUID() до блока try. Этот API требует защищённого контекста ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)). При обычном HTTP-доступе по адресу компьютера в локальной сети API может отсутствовать, а кнопка останется в состоянии «Обновляем прогресс…».

Перед демонстрацией с другого устройства проверить этот путь. Для исправления — предусмотреть генерацию идентификатора в поддерживаемом окружении и обработку исключения с восстановлением кнопки. localhost-прогон не подтверждает работу по LAN.
